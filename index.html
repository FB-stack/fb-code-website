How we work

The full method →
Step 01

Map

We sit with the people doing the work and write down the real process, step by step, with timings. Nothing gets specified yet.

Step 02

Scope

A written spec, an architecture, and a build plan you own outright — useful to you even if someone else builds it.

Step 03

Build

Two-week iterations against a shared board. Working software at the end of each one, deployed where you can actually use it.

Step 04

Operate

Deployment, monitoring, and handover documentation your own team can take the system over from whenever it wants to.

How we prove it moved

Three measures

Output is a number, not a feeling. We agree the baseline before the first commit, so the result is not a matter of opinion afterwards.

Cycle time

How long one unit of work takes end to end, before and after. The number that says whether the process changed or just moved.

Manual steps removed

Every hand-off a person no longer performs, counted and costed against the hours it used to take each week.

Rework rate

Work that had to be done twice. Automation is only a gain if it does not quietly create a new class of failure.
